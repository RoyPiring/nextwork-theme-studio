# Development

There is no build step and no dependency to install. Edit a file, click
**Reload** on the extension card in your browser, then refresh the page.

Node 18 or newer is needed only for the tools below. Python 3 with Pillow is
needed only for the image tools.

## Everyday commands

```bash
npm test              # unit tests
node tools/audit.js   # repository checks, run before every commit
node tools/build.js   # package a folder for each browser into dist/
```

## What continuous integration runs

Four jobs. They run on every pull request, on every push to `main`, once a
week on a schedule, and on demand from the Actions tab:

| Job | Where | What |
| --- | --- | --- |
| `checks` | Ubuntu **and** Windows | `node --test` and `tools/audit.js` |
| `generated` | Ubuntu | Regenerates the scenery and gallery, fails if they drift |
| `package` | Windows | `tools/build.js`, then checks each archive exists and is not empty |
| `audit` | Ubuntu | Passes only if the three above did |

`audit` exists to have a name that never changes. A required status check is
named after the job reporting it, so putting the matrix under that name would
have produced `audit (ubuntu-latest)` and `audit (windows-latest)`, leaving the
branch rule pointing at a check that no longer exists and quietly requiring
nothing.

Packaging runs on Windows because that is the platform the packaging code
targets, and because a Windows-only bug once shipped archives that could not be
installed anywhere while the build reported success.

Two of the audit's checks exist to keep this arrangement honest: one fails if a
job is added and left out of `audit`'s `needs`, or listed there but never read;
the other fails if any action is referenced by tag rather than by commit SHA.
Both were previously guaranteed by a comment.

## The audit

`tools/audit.js` is the important one. It checks that:

- the manifest is valid and the version matches `package.json`
- every file the manifest and the HTML pages reference exists
- permissions stay minimal
- no script makes a network request or uses unsafe code
- all 18 themes clear the contrast floor
- every theme has a wallpaper and its own scenery
- both stylesheet variants build for every theme

Every check exists because that exact problem happened at some point.

## Tests

```bash
npm test
```

Tests live in `tests/` and use `node:test`, so there is nothing to install.

- `tests/engine.test.js` covers colour maths, CSS generation and scenery.
- `tests/content.test.js` covers the content script, driven through a small
  DOM stand-in in `tests/harness.js`.

`tests/harness.js` is not a browser. It implements only what the content script
touches, which keeps it short enough to read and to trust. Anything the script
starts using that is missing there will throw rather than quietly do nothing.

When fixing a bug, add the test first and confirm it fails without the fix.

## Other tools

```bash
node tools/export-scenes.js    # save the drifting layers as SVG files
node tools/gallery.js          # rebuild the theme grid used in the README
node tools/contact-sheet.js    # view all 18 scenes on one page
node tools/theme-info.js       # print a theme's resolved palette
node tools/split-repro.js      # reproduce the split-view bleed-through
```

Regenerating wallpapers, scenery and the icon is covered in
[ASSETS.md](ASSETS.md).

## Previewing the popup

The popup and the editor are ordinary web pages, so they can be opened over
a local server to inspect layout without loading the extension:

```bash
python -m http.server 8777
```

Then open `http://localhost:8777/src/popup.html`. The controls will not work,
because the browser extension APIs are absent, but the layout renders.

## Project layout

```
manifest.json          Settings the browser reads
src/theme-engine.js    Colours, contrast maths, and CSS generation
src/scenes.js          The mist and dust that drift over each wallpaper
src/wallpapers.js      Picture wallpapers, stored inside the file
src/content.js         Adds the stylesheet to the page
src/background.js      Keyboard shortcut and toolbar icon
src/popup.*            The panel behind the toolbar icon
src/options.*          The editor
art/                   Source pictures. Build input only, nothing here ships
assets/                The drifting layers saved as SVG files you can open
icons/                 Extension icon, generated by tools/make-icon.py
tools/                 Checks, packaging and image tools
tests/                 Unit tests
docs/                  These guides
```
